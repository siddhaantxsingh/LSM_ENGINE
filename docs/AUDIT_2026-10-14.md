# Audit, 2026-10-14

Scope: WAL/MANIFEST crash consistency, MVCC, compaction, corruption
handling, model-based testing, RocksDB comparison, C ABI safety.
Baseline: `docs/evidence/2026-10-14/baseline.md`. Every fix has a test
that failed before the fix (`docs/evidence/2026-10-14/failing_first.log`).

## Defects

| ID | Severity | Defect | Status | Test |
|---|---|---|---|---|
| D1 | Critical | `Db::flush()` froze the memtable while a write leader was still inserting into it without the lock. The flushed table missed the write, its WAL was deleted, and the memtable was dropped: 340-978 acknowledged writes lost per run, without any crash. | Fixed | `regressions::d1_flush_does_not_lose_concurrent_writes` |
| D2 | Critical | A corrupt record in the middle of the MANIFEST, or an empty MANIFEST, ended replay silently; the engine then deleted live tables as "unreferenced". | Fixed: recovery fails unless the history is complete and coherent; nothing is deleted before it checks out | `d2_*`, `d2b_*` |
| D3 | High | A corrupt record in the middle of a WAL ended replay silently, dropping all later synced writes. | Fixed: new record format (length has its own CRC) and `WalRecoveryMode` | `d3_mid_wal_corruption_is_an_error` |
| D4 | High | SST footer and block handles were trusted: a large size overflowed `size + 4` (panic) or requested a huge allocation. | Fixed: bounds-checked against file length | `d4_bad_footer_size_is_corruption_not_panic` |
| D5 | High | `Db::iter` skipped L0 tables that failed to open; scans silently returned fewer keys. | Fixed | `d5_iter_reports_unopenable_table` |
| D6 | High | `DbIterator`'s `Iterator` impl yielded plain tuples, so a read error looked like the end of the data. | Fixed: items are `Result`; an incomplete scan ends with `Err` (API change) | `regress_scan_api::d6_*` |
| D7 | High | No directory fsync after creating WAL and SST files; after a power loss the MANIFEST could name a missing table. | Fixed | `d7_new_files_survive_power_loss`, `crash_sim` |
| D8 | Medium | Out-of-range level numbers or short keys in a MANIFEST record caused a panic. | Fixed: validated in decode | `version::regression_tests::d8_*` |
| D9 | Medium | A live table missing on disk was only noticed on a read that touched it. | Fixed: checked at open (existence and size) | `d9_missing_table_refuses_open` |
| D10 | Medium | A zero-filled WAL tail (file length updated, data not written) was rejected after a crash. | Fixed | `d10_zero_filled_wal_tail_is_a_torn_tail` |
| D11 | High | Found by the new corruption sweep: a bit flip in the last MANIFEST record looked like a torn write, so a committed edit was dropped and acknowledged data disappeared. | Fixed: records end with a non-zero trailer byte; the MANIFEST rejects a complete last record with a bad checksum | `corruption::bit_flips_in_every_file_type_are_detected` |
| D12 | Low | Clippy failed on the current toolchain. | Fixed | CI `lint` job |
| D13 | High (honesty) | The README described a C ABI, test files, docs and fixes that did not exist (see baseline). | Fixed: README rewritten; C ABI implemented | this audit |

Also changed: if `CURRENT` is missing but tables exist, open refuses
instead of creating an empty database and deleting the tables; after a
torn MANIFEST tail, unreferenced tables are renamed `*.sst.lost` instead
of deleted.

## Open issues and limitations

- A bit flip inside the payload of the very last WAL record is
  indistinguishable from a torn write; `TolerateCorruptedTail` (default)
  drops that record. `AbsoluteConsistency` reports it instead. Tested.
- The on-disk log format changed; old databases cannot be opened (see
  `OWNER_ACTIONS.md`).
- Mutation check: 11 of 14 injected bugs were caught. Survivors: the D1
  mutant was equivalent (a second wait loop still covers it); the bloom
  false-negative mutant only fires for key lengths the tests do not use;
  "MANIFEST mid-log corruption tolerated" was still refused for another
  reason ("no records") in the D2 test. The first run's log is
  `mutation_check.log`; that run also exposed a script bug (restored
  files kept an old mtime, so cargo reused a mutated build), fixed in
  `scripts/mutation_check.sh` but the full run was not repeated.
- `SimFs` models strict POSIX power loss; it is not a real power cut.
- Memtable iteration copies the whole memtable per iterator; scans on a
  full memtable are slower than they need to be. Not changed.
- No compression, one background thread, no bounded table cache
  (unchanged from the original design notes).
